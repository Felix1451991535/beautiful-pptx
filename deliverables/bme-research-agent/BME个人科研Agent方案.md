# BME 个人科研 Agent 方案：能力清单与系统设计

版本 v1.0 ｜ 2026 年 10 月 ｜ 适用对象：生物医学工程（BME）方向、以个人为主推进课题的研究者

## 0. 一句话结论

一个合格的个人科研 Agent，不是“更会聊天的大模型”，而是**一个长期记得你整个课题、会主动盯进度、会在你犯错前拦住你、会拿证据反驳你的“虚拟师兄 + 实验秘书 + 审稿人”**。它比 Claude Code、Codex、AI PPT、Deep Research 这类通用工具强，不是因为底层模型更聪明（大家调用的都是同一批模型），而是因为它多了四样东西：**课题级长期记忆、BME 领域工具箱、实验闭环（做完实验回来更新判断）、主动提醒与反向引导**。

本方案基于对 Google DeepMind Co-Scientist（Nature 2026）、FutureHouse Robin 与 Edison Kosmos、Stanford Biomni、Sakana AI Scientist、Claude Code / Codex 生态、主动式科研助手 Omakase，以及 LAB-Bench、BioProBench、BenchBench-Protocol 等湿实验评测的公开资料整理，参考链接见附录 C。

## 1. 调研结论：现在的“AI 科学家”能做到什么、缺什么

| 系统 | 擅长 | 对一人 BME 课题的不足 |
|---|---|---|
| Google Co-Scientist（Nature 2026） | 多智能体生成、互评、锦标赛排序、进化假设；在药物重定位、新靶点、耐药机制上有实验验证 | 只做“想法”，不陪你做实验、不管你的进度和数据 |
| FutureHouse Robin / Edison Kosmos | 文献 + 数据分析闭环；Kosmos 用“结构化世界模型”维持长程连贯，单次读约 1500 篇论文、跑约 4.2 万行代码 | 独立专家核验：报告陈述整体 79.4% 正确，但“综合解读类”陈述只有 57.9% 正确——越往结论走越需要人把关 |
| Stanford Biomni | 通用生物医学 Agent：150 个专用工具、105 个软件包、59 个数据库（UniProt、PDB、GEO、ClinVar、ChEMBL、ClinicalTrials.gov 等） | 偏分子/组学，对器械、材料、信号、影像、力学等 BME 工程侧覆盖弱；不懂你的课题历史 |
| Sakana AI Scientist v2（已发表于 Nature） | 机器学习方向从想法到论文全自动，论文通过了同行评审 | 只限计算实验，湿实验无能为力 |
| Claude Code / Codex CLI | 写代码、跑分析、Skills / MCP / 子智能体可扩展，是搭 Agent 的最好“底座” | 本身是通用编程助手，没有科研流程、没有领域规范、不会主动找你 |
| Deep Research 类产品 | 一次性多源检索 + 长报告 | 你要自己把课题压缩成一句话去问；报告长而不可执行 |
| AI PPT / 写作工具 | 出稿快 | 只解决最后一步，且容易编造引用 |
| Omakase（2026 研究原型） | 监控你的项目文档，自动发起文献查询，把长报告提炼成“针对你项目的可执行建议”，并能用文献反驳你的论断 | 只覆盖文献环节，是本方案“主动性”设计的重要参考 |

**湿实验是当前 AI 的最大短板，方案必须针对性设计：**

- BioProBench：模型直接生成实验方案时，必要步骤的召回率低于 43%；即便接入方案语料库检索，仍会漏掉约 38% 的必要步骤。
- LAB-Bench 的 ProtocolQA（方案纠错）上，主流模型准确率大约在 50%–60%。
- BenchBench-Protocol（Benchling，2026）：模型的建议“纸面上合理”，但会忽略仪器校准、把明显不纯的样品当纯品、忽视手法细节。
- SycEval（Stanford）：GPT-4o、Claude Sonnet、Gemini 1.5 Pro 在被用户反驳时出现“附和”的比例约 58%。一个只会顺着你说的 Agent 会放大错误。

**由此得出的设计原则：** Agent 负责“想全、查全、算对、记全、提醒到”，人负责“动手、判断、拍板、担责”。实验方案永远以已发表/实验室验证过的方案为底稿，Agent 做补全和纠错，不从零生成。

## 2. 定位：它是什么，不是什么

**它是：**

- 你课题的“第二大脑”：记得每一个假设、每一次实验、每一次失败和原因、导师的每条意见。
- 你的实验秘书：排期、倒计时、试剂与设备提醒、记录、复盘。
- 你的“Reviewer 2”：在你投入时间和样本之前，先挑毛病。
- 你的分析员和写作助手：数据处理、统计、作图、论文/基金/专利初稿。

**它不是：**

- 不是替你做实验、替你下结论、替你当作者的“全自动科学家”。
- 不是只会附和的聊天机器人：遇到设计缺陷必须明确反对。
- 不是数据生成器：绝不编造数据、补齐缺失值去“凑显著”。

## 3. 核心能力清单（12 大模块）

下表是“合格线”。打 ★ 的是让它明显强于通用工具的关键能力。

| 模块 | 必备能力 | 产出物 |
|---|---|---|
| ★1 课题大脑（长期记忆） | 结构化记录研究目标、假设树、实验记录、结果、失败原因、决策及理由、导师意见、截止日期；每次对话前自动加载相关上下文 | 课题知识库、假设树、决策日志、失败库 |
| 2 文献情报 | 检索 PubMed、Europe PMC、OpenAlex、Semantic Scholar、arXiv/bioRxiv/medRxiv、IEEE Xplore、专利库、ClinicalTrials.gov；全文阅读含图表；每条引用必须能打开核验（DOI/PMID） | 文献卡片、综述矩阵、每周文献雷达 |
| ★3 假设与选题 | 生成多个竞争假设 → 互相批判 → 排序（参考 Co-Scientist 锦标赛机制）；新颖性查重；可行性评估（设备、经费、周期、技能） | 假设排行榜、选题评估表 |
| ★4 实验设计 | 样本量/功效分析、对照组设计（阴性/阳性/假手术/载体）、随机化与盲法、DOE（正交/响应面）、变量与混杂控制、预注册；按 ARRIVE 2.0 等规范自查 | 实验设计书、样本量计算书、预注册草稿 |
| ★5 失败预演（Pre-mortem） | 实验开始前列出“这次最可能失败的 10 个原因”并逐条给预防措施；对照你自己的失败库和文献常见坑 | 风险清单、预防清单 |
| 6 实验陪跑 | 把方案拆成逐步检查表；计时与关键节点提醒；稀释/浓度/摩尔/细胞铺板/剂量换算计算器；记录实际操作偏差 | 当日实验检查表、电子实验记录 |
| ★7 故障排查 | 结果异常时按“试剂→样品→仪器→操作→设计→分析”顺序排查，结合失败库和文献，给出最小代价的验证实验 | 排查树、下一步验证建议 |
| 8 数据分析 | Python/R 沙箱执行；统计检验选择与前提检查；图像分析（ImageJ/Fiji、CellProfiler）；信号处理（MNE、SciPy）；影像（3D Slicer、MONAI）；力学/仿真（FEBio、COMSOL 后处理）；全部脚本留档可复现 | 分析脚本、图表、统计报告 |
| 9 写作与发表 | 论文各部分初稿、方法学按规范清单写全、图注、投稿信、基金本子、专利交底书、组会/答辩 PPT；模拟审稿与回复审稿意见 | 文稿、审稿模拟报告、回复信 |
| 10 合规与伦理 | 判断是否需要伦理审批（人体/动物/人类遗传资源）、生物安全等级、医疗器械法规路径（NMPA/FDA、ISO 10993 生物相容性、ISO 13485、IEC 62304、IEC 62366-1）；患者数据脱敏 | 合规检查表、伦理申请材料草稿 |
| 11 项目管理 | 里程碑、甘特图、试剂库存与有效期、设备预约、经费台账、论文/会议/基金截止日期 | 周计划、风险看板 |
| ★12 主动性与反向引导 | 事件触发的主动提醒；对你的决定提出质疑；苏格拉底式追问；知道何时保持沉默 | 见第 4 章 |

## 4. 主动性与反向引导：让它像“真人搭档”的关键

这是你最在意的效果，也是它和所有“你问它答”型工具的根本区别。设计参考了 Omakase（监控项目文档、主动发起查询）、PASK（需求检测 + 长期记忆 + 主动执行）以及“主动记忆 Agent”研究——后者发现，只在关键时刻注入提醒，效果优于“一直提醒”和“从不提醒”。

### 4.1 主动触发器（它什么时候会主动找你）

| 触发事件 | Agent 的主动动作 |
|---|---|
| 你写下一个新实验计划 | 自动做样本量检查、对照组检查、失败预演；缺项直接标红 |
| 实验日前一天 | 推送明日检查表：试剂是否够、是否过期、设备是否已预约、细胞/动物状态是否就绪 |
| 实验进行中 | 按方案节点计时提醒（孵育、离心、换液、取材时间点） |
| 实验结果上传 | 自动分析 → 与预期对比 → 若异常则启动故障排查 → 更新假设树的置信度 |
| 连续两次同类失败 | 主动叫停：“建议先做最小验证实验，再继续消耗样本” |
| 文献雷达发现相关新论文 | 只推送与你当前假设直接相关的 1–3 篇，并说明“它支持还是反驳你的哪个假设” |
| 截止日期临近 | 倒排计划，指出关键路径上已经落后的任务 |
| 你很久没更新某条线 | 询问是放弃、搁置还是遗忘，并记录原因 |
| 你准备下结论或写论文 | 自动跑“结论-证据”对照：每个结论背后是哪组数据、n 是多少、是否预先设定 |
| 涉及人体/动物/患者数据 | 先提示伦理与数据合规，未确认前不进入下一步 |

### 4.2 反向引导规则（防止它变成“马屁精”）

把下面这些写进 Agent 的系统规则，并定期抽查：

1. **先质疑再执行**：对每个实验设计，至少提出一个最强反对意见和一个替代方案。
2. **苏格拉底式追问**：“你的阴性对照是什么？”“如果结果是阴性，你能得出什么结论？”“这个效应量是从哪来的？”
3. **不轻易改口**：你反驳它时，必须要求你给出证据；没有新证据就坚持原判断，并说明理由。
4. **分清三类陈述**：每句话标注“来自文献 / 来自你的数据 / 是推测”，推测类必须明说。
5. **主动报坏消息**：数据不支持假设时第一时间说，不包装、不找补。
6. **拒绝 p-hacking**：不接受“换个检验方法再试试”“去掉几个离群点看看”这类请求，除非预先设定或有正当理由并记录在案。
7. **知道何时沉默**：提醒分为“必须处理 / 建议关注 / 仅记录”三级，每天主动打扰不超过设定次数，避免提醒疲劳。

### 4.3 一天的样子（示例）

- 早上：推送“今日三件事”+ 一篇与你假设直接相关的新文献摘要（附支持/反驳判断）。
- 实验前：你拍照上传试剂标签，它核对批号、有效期、浓度并生成当日检查表。
- 实验中：按节点计时提醒；你语音说“第 3 孔加样多了”，它自动记入偏差记录。
- 下午：上传荧光图，它批量定量、出图，并提示“对照组荧光强度比上周低约 30%，建议检查抗体批次”。
- 晚上：生成当日实验记录、更新假设树，并列出“明天开始前你必须决定的一件事”。
- 每周：周报 + 进度风险 + “本周最值得怀疑的一个结论”。

## 5. 它如何真正提高实验成功率

| 机制 | 解决的问题 |
|---|---|
| 功效分析 + 预注册 | 样本量不够、事后改分析导致结果不可信 |
| 对照组与盲法强制检查 | 设计缺陷导致实验白做 |
| 失败预演 + 个人失败库 | 重复踩同一个坑 |
| 以验证过的方案为底稿 + 逐步检查表 | AI 生成方案漏步骤（BioProBench 显示漏步骤是主要失败模式） |
| 预实验（Pilot）建议 | 大批量投入前先用小样本验证关键参数 |
| 试剂/设备/细胞状态前置检查 | 非科学原因的失败（过期、没预约、细胞代数过高） |
| 结构化故障排查 | 失败后盲目重复 |
| 结论-证据对照 | 过度解读、把探索性结果当确证性结果 |

## 6. 系统架构

### 6.1 分层设计

| 层 | 内容 | 推荐实现 |
|---|---|---|
| 交互层 | 手机端随时可用（语音、拍照、文件）；电脑端深度工作 | 飞书/企业微信/Telegram 机器人 + Web 看板；电脑端 Claude Code / Codex / Cursor |
| 编排层 | 主 Agent 负责理解意图与分派；子 Agent 各司其职；定时任务驱动主动性 | Claude Agent SDK、OpenAI Agents SDK 或 LangGraph；定时器（cron） |
| 记忆层 | 结构化数据库（实验、样本、试剂、决策）+ 文献/笔记向量库 + 课题“世界模型”文档 | SQLite/PostgreSQL + 向量库（Chroma/pgvector）+ Markdown 课题档案 |
| 工具层 | 文献检索、文献管理、代码执行、数据库查询、日历、电子实验记录 | MCP 服务器：PubMed、OpenAlex、Semantic Scholar、Zotero、Jupyter、日历；Biomni 工具集 |
| 模型层 | 多模型按任务路由；可接中转站 | 自建 LiteLLM 或 New-API 网关（见第 7 章） |
| 安全与审计层 | 每次调用的模型、提示词、输出、引用全部留档；敏感数据隔离 | 调用日志 + 引用核验器 + 数据脱敏 |

### 6.2 子 Agent 分工（“虚拟课题组”）

| 角色 | 职责 |
|---|---|
| 项目秘书 | 记忆维护、日程、提醒、周报 |
| 文献官 | 检索、精读、引用核验、文献雷达 |
| 假设官 | 生成与排序假设、新颖性检查 |
| 实验设计官 | 设计、样本量、对照、失败预演、检查表 |
| 统计官 | 检验选择、前提检查、效应量、多重比较校正 |
| 数据分析官 | 写脚本跑分析、出图、可复现留档 |
| 批判官（Reviewer 2） | 专门挑错，对所有重要产出做独立审查 |
| 写作官 | 论文/基金/专利/PPT 初稿 |
| 合规官 | 伦理、生物安全、法规、数据隐私 |

批判官最好使用与执笔 Agent 不同厂商的模型，交叉验证能减少同一模型的系统性盲区。

## 7. 关于接入 API 中转站

你提到会接中转站那一批 API，这完全可行（大部分中转站都兼容 OpenAI 接口格式），但科研场景有几个必须注意的点：

| 风险 | 说明 | 对策 |
|---|---|---|
| 数据泄露 | 中转站能看到你发出的全部内容 | 未发表数据、患者数据、专利核心内容不走第三方中转；用官方 API 或本地模型 |
| 模型被替换或降级 | 部分中转站会用便宜模型冒充高端模型 | 准备一套固定的“验真测试题”定期抽测；记录每次返回的模型标识 |
| 稳定性 | 渠道随时可能失效 | 配置多条渠道 + 自动故障切换 |
| 可复现性 | 不知道到底用了哪个模型版本，论文方法学写不清楚 | 日志记录模型名、版本、时间、参数 |
| 合规 | 涉及人类遗传资源、患者隐私的数据有法律约束 | 敏感数据本地处理，只把脱敏后的结果发给云端模型 |

**推荐做法**：在自己的电脑或服务器上部署一个网关（LiteLLM 或开源 New-API），把官方 API 和各家中转站都接到网关后面，Agent 只连网关。这样可以统一做路由、限额、故障切换、日志和敏感词拦截，换渠道不用改 Agent 代码。

**按任务选模型（示例策略）：**

| 任务 | 模型档位 |
|---|---|
| 假设生成、实验设计、批判审查、故障排查 | 最强推理模型（两家不同厂商交叉） |
| 写代码、跑分析 | 强编程模型 |
| 文献初筛、摘要、格式整理、提醒文案 | 便宜快速模型 |
| 图片/图表/凝胶/荧光图理解 | 多模态模型 |
| 敏感数据处理 | 本地开源模型 |

## 8. 与市面工具的对比

| 维度 | 通用聊天 / AI PPT | Claude Code / Codex | Deep Research | 本方案 Agent |
|---|---|---|---|---|
| 记得整个课题历史 | 弱 | 依赖手写说明文件 | 无 | ★ 结构化长期记忆 |
| 主动提醒 | 无 | 无 | 无 | ★ 事件 + 定时触发 |
| 反驳你 | 容易附和 | 偶尔 | 不针对你 | ★ 规则化反向引导 |
| 实验设计与统计把关 | 泛泛而谈 | 能算不会管 | 无 | ★ 强制检查清单 |
| 湿实验陪跑与排查 | 无 | 无 | 无 | ★ 检查表 + 失败库 |
| BME 领域工具 | 无 | 需自己接 | 无 | ★ 预装领域工具包 |
| 引用可靠性 | 常编造 | 视配置 | 较好 | ★ 强制核验 DOI/PMID |
| 写代码跑分析 | 弱 | 强 | 无 | 强（底座就是它们） |

结论：**用 Claude Code / Codex 当“手”，用本方案的记忆、流程、领域工具和主动机制当“脑和习惯”**，这是一个人就能搭出来、并且确实比单独使用任何一个工具都强的组合。

## 9. 边界与红线

1. 绝不编造数据、图像或引用；找不到就说找不到。
2. 每条文献引用必须能通过 DOI/PMID 打开核验，核验失败的自动删除并告知。
3. 结论由你下，Agent 只给证据和置信度。
4. 涉及人体、动物、人类遗传资源、患者数据的研究，未完成伦理与合规确认前不推进。
5. 不帮忙做 p-hacking、不选择性报告结果。
6. 保留全部提示词与输出记录。Nature 等期刊要求披露大模型使用情况，不接受 AI 为作者，并鼓励提交提示词与回复记录。
7. 生物安全：不提供可能被滥用的危险病原体或毒素相关操作细节。

## 10. 落地路线（分阶段）

| 阶段 | 目标 | 交付内容 | 验收标准 |
|---|---|---|---|
| 阶段一：最小可用版 | 有记忆、能检索、会提醒 | 课题档案模板 + 文献检索 MCP + 引用核验 + 每日/每周推送 + 实验记录 | 能准确复述你课题现状；引用 100% 可打开 |
| 阶段二：实验把关 | 提高实验成功率 | 实验设计检查清单、样本量计算、失败预演、检查表、失败库、批判官 | 每个新实验都经过检查；重复失败明显减少 |
| 阶段三：分析与写作 | 数据到论文的闭环 | 数据分析沙箱、领域工具包、写作官、审稿模拟 | 分析脚本可一键复现；论文方法学按规范清单无缺项 |
| 阶段四：主动与进化 | 像真人搭档 | 事件触发器、假设树置信度更新、文献雷达、提醒分级与降噪 | 你觉得提醒“有用的多、烦人的少” |

## 11. 怎么评估它合不合格

| 指标 | 含义 |
|---|---|
| 引用准确率 | 引用真实存在且内容对得上的比例，目标 100% |
| 实验一次成功率 | 不因可预防原因失败的实验比例，与使用前对比 |
| 设计缺陷拦截数 | 实验前被它发现并修正的问题数量 |
| 想法到实验的周期 | 从提出假设到第一次正式实验所需的工作量 |
| 提醒命中率 / 误报率 | 有用提醒占比；被你标为“无用”的提醒占比 |
| 坚持正确判断的比例 | 你无证据反驳时它不改口的比例（用测试题抽查） |
| 可复现率 | 分析结果能被脚本重新跑出的比例 |

## 附录 A：课题档案模板（Agent 的“世界模型”）

- 研究总目标与科学问题
- 假设树：每个假设的状态（待验证 / 支持 / 反驳 / 搁置）、置信度、支撑证据
- 实验登记：编号、目的、对应假设、设计、样本量、日期、结果、偏差、结论
- 失败库：现象、根因、预防措施
- 决策日志：日期、决定、理由、谁拍板
- 资源：试剂（批号、有效期、库存）、设备、样本、经费
- 时间线：里程碑、截止日期、组会、投稿、基金
- 导师与合作者意见记录

## 附录 B：系统规则核心片段（可直接放进 Agent 的系统提示词）

- 你是我的 BME 课题搭档，不是助手。你的首要目标是让我的研究结论真实、可复现。
- 回答前先读取课题档案中与问题相关的部分；不确定时先问我，不要猜。
- 对任何实验设计，先指出最大风险和缺失对照，再给方案。
- 每条事实标注来源：文献（附 DOI/PMID）、我的数据（附实验编号）、或推测。
- 我反驳你时，若我没有新证据，请坚持并解释；若有新证据，明确说明你为何改变判断。
- 发现我的数据不支持假设、计划有漏洞、或进度落后时，必须主动、直接地告诉我。
- 绝不编造数据、图片或文献；绝不协助选择性报告或事后调整分析以追求显著性。
- 涉及人体、动物、人类遗传资源或患者数据时，先确认伦理与合规状态。
